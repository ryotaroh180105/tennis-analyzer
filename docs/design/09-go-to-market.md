# 09. マーケティング・差別化・事業設計

前提：[08](08-operations.md) の再計算済みコストモデル（Pro処理費55〜125円/試合＋月次原価）が
価格設計の制約。競合・市場の定量データは調査結果（§競合調査メモ）に基づく。

## カテゴリ定義：「分析アプリ」ではなく「継続AIコーチング」

SwingVisionの土俵（＝試合分析アプリ）で「日本語版・オムニ対応版」として戦う限り、
上限は**地域2位のローカライズ製品**である。本アプリのカテゴリは：

> **記録 × 継続 × 社会性で上達サイクルを回す、テニスの継続AIコーチング**
> （比喩：テニスの Strava。1回の解析精度でなく、続くことに価値の中心を置く）

- 日本ロコ要素（LINE・オムニコート・草トー文化）は**カテゴリではなくGTM戦術**。
  初期市場（日本）で最速でループを回すための手段であり、輸出しない前提で設計する
  （チャネル抽象・i18n・court-spec外出しは [07](07-advice-delivery.md) / [10](10-phase0-implementation-plan.md) / [05](05-tech-stack.md) 参照）。

## 拡張戦略（geo / sport）— 世界シェアを狙う経路

| 段階 | 市場 | 鍵 |
|---|---|---|
| 1（〜PMF） | 日本・個人（社会人サークル） | オムニ対応・LINE・編集自動化ループの確立 |
| 2 | 日本・B2B2C（スクール・大会） | 大会インフラ化（後述）で閉グラフを越える |
| 3 | 台湾・タイ（LINE圏・コート環境も近い） | チャネルそのまま・言語キー追加のみで展開（i18n設計が効く） |
| 4 | 欧米 | チャネル差し替え（WhatsApp/Push/Email）。コート環境マトリクスのクレー/ハードのセルを充填 |
| 並行 | パデル（欧州・中南米）・ピックルボール（北米） | court-spec.yaml＋競技別taxonomyで検討。CVステージの改修範囲を寸法パラメータに限定する規約（[05](05-tech-stack.md)）が展開コストを決める |

- **世界一を狙うか否か自体を意思決定として明示する**：本設計は「狙う」を選び、
  Phase 0〜1の実装コストがほぼ変わらない範囲の布石（チャネル抽象・i18nキー・court-spec規約・
  moatの世界共通化）だけを先に打つ。海外向け機能の実装は行わない（yagni）。

| 優先 | セグメント | 特徴 | 獲得経路 |
|---|---|---|---|

| 2 | テニススクール生（一般・ジュニア） | 継続率が高い・コーチが介在 | スクール・コーチ提携（B2B2C。国内に既存競合あり：Tennis Labo等） |
| 3 | 部活（中高） | ボリューム大・決済者が別・未成年同意が必要 | チーム一括導入（Phase 2以降。保護者同意はチーム経由で取得） |

- 最初の1年はセグメント1に集中。**ただし利用頻度の想定は保守的に置く**：
  サークル層の「撮影された試合」は月1〜2本が現実線（毎週テニスをしても、三脚設置＋
  1時間録画＋アップロードまで完遂するのは一部）。**月4〜8試合の想定は置かない**。
  したがってProの転換動機は「本数」でなく「保持・傾向分析・アドバイス」に置く（価格設計参照）。

## 差別化と moat

### 差別化の核（2つの構造）

1. **誠実さの設計** — 信頼度を隠さない。「誤った断定より未分類」。
   競合の「自動だが間違う」への直接の回答であり、コーチング製品の信頼の核。
2. **継続の設計** — 解析して終わりでなく「振り返る→改善する→また練習する」ループを
   配信で駆動する。**機能としての参入障壁は低い**（競合がLLM層を足すのは数ヶ月仕事）。
   だから差別化の主張は「競合がいない」ではなく「**先行蓄積が模倣より速い**」に置く。

### moat（時間で複利がつく資産）— 世界共通の資産として定義する

| 資産 | 蓄積構造 | 地理的可搬性 |
|---|---|---|
| **修正ラベル収集パイプライン** | サポート報告・ユーザー修正→ゴールデンセット→回帰→改善の仕組み（[08](08-operations.md)）。コート環境×撮影条件のマトリクスを埋める。オムニは最初のセルに過ぎない | **世界共通**（仕組み自体が資産） |
| **AdviceLog（アドバイス→行動変容→成果）** | どの介入がどの層に効いたかの対応データ（[07](07-advice-delivery.md)）。競技・言語を越えて移転可能な唯一の学習資産。**蓄積最大化のためFreeにも週次ダイジェストの縮約版を配信**し、リアクションデータを取る | **世界共通・競技横断** |
| 日本環境の正解データ | オムニ・スマホ撮影の学習データ | 日本ローカル（初期市場の防御） |
| YAMLルール資産 | コーチ知見のルール化・taxonomyバージョンの蓄積 | 言語キー追加で可搬 |

## 獲得：3層のループ設計

### 第1層：クレーム導線（サークル内。K係数の主エンジン）

従来案「共有→視聴→登録」の弱点：共有先は**同じ試合に映っている仲間**であり、
その試合は解析済みなので登録動機が弱い。またサークルの撮影者は1人いれば足りるため、
**登録がサークル単位で1アカウントに収束する**。これを逆手に取る：

```
撮影者がアップロード → サークルLINEに共有
  → 視聴ページに「この試合に映っているのはあなた？ **自分のスタッツを受け取る**」
  → 対戦相手・パートナーが自分をクレーム（撮影者の承認制）
  → 同じ1本の動画から、映っている全員（ダブルスなら4人）がアカウント化
```

- 登録動機を「他人の試合を見る」から「**自分のデータを受け取る**」に変える。
  1動画＝最大4アカウントで、1サークル1撮影者問題がそのまま増幅器になる。
- プライバシーと表裏一体：クレーム機能は本人確認＋撮影者承認を必須にし、
  「勝手に他人のスタッツを見る」を構造的に排除（法的整理とセットで設計）。
- データモデルへの布石：`PointRecord` の player は既に匿名トラックID。
  クレーム＝トラックIDとアカウントの紐付けであり、Phase 2で実装可能（[02](02-architecture.md)）。

### 第2層：大会インフラ化（閉グラフを越える。Phase 2の主戦略）

サークル内ループはグラフが閉じており飽和する。**新規グラフ同士が接触する唯一の場が草トー大会**：

- 大会主催者に無償提供：「大会の全試合が自動で動画化・ハイライト化される」は
  主催者の集客材料＋参加者への付加価値。参加者は自分の試合をクレームして持ち帰る。
- データモデルに `Tournament`（Match の親）と主催者ロール、コーチ閲覧権限の**スキーマだけ**
  Phase 1 で用意（実装はPhase 2。後からの追加はマイグレーション費用が大きい）。

### 第3層：補助チャネル

- テニス系YouTuber・コーチへの無償提供（増幅器）
- SEO：「テニス 動画 編集」等の実用クエリ（記事は薄く、実物デモを厚く）
- **有料広告はK係数とリテンションが立つまで打たない**

### ファネルの仮定値（Phase 0〜1 で実測して置換する）

| 段 | 仮定 | 実測できたら |
|---|---|---|
| アップロード→共有 | 50% | [01](01-mvp-scope.md) の成功指標 |
| 共有→ユニーク視聴 | 3人/共有 | サークルLINEの既読規模から |
| 視聴→クレームまたは登録 | 10%（クレーム導線込み。導線なしの登録のみなら2〜3%想定） | ここが最大の不確実性 |
| 登録→初回アップロードまたはクレーム完遂 | 40% | Wi-Fi待ちアップロードが障壁（下記） |

- この仮定でK≒0.2〜0.5/月・アクティブ。**K<1を前提**とし、獲得はループ＋大会＋提携の
  ミックスで設計する（ループ単独でのオーガニック成長は想定しない）。
  K係数が0.1を下回り続けたらクレーム導線のUX改善に投資、0.05未満が3ヶ月続いたら
  獲得戦略を大会・B2B2C主導に転換する（撤退ラインの明示）。

## オンボーディング（導入体験）

初回体験の敵は「撮影ガイド読了→次の試合まで待つ」の断絶と、**4〜6GBのアップロード障壁**：

1. 登録はLINEログイン＋メール取得（[07](07-advice-delivery.md)）
2. 登録直後に**過去のスマホ動画をそのまま1本アップロードさせる**（Free枠に数えない）。
   画角が悪くても**縮退モードで編集だけは必ず返し**（[03](03-recording-guidelines.md)）、
   「次はこう撮るともっと分かる」を結果として体験させる。ダメ出しだけで終わる初回体験を作らない
3. アップロードは**Wi-Fi待ちキュー＋中断再開**を標準に（モバイル回線で4〜6GBは
   完遂率を潰す第一要因。[10](10-phase0-implementation-plan.md) のアップロードAPI要件）。
   「Wi-Fiに繋がったら自動で送信します」を初回に説明
4. 初回解析完了の通知→編集済み動画→共有ボタンまでを1画面で
5. 撮影ガイドは「次の試合の前」にリマインド配信
