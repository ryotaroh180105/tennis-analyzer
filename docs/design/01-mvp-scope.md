# 01. MVPスコープとフェーズ計画

## 結論

**ユースケース①（試合動画の分析）から着手する。ただし①を3段階に分解し、
最初のリリース（Phase 0 = MVP）は「動画編集の自動化」だけに絞る。**
ユースケース②（フォーム解析。サーブから着手し主要ショット全種へ拡張）はPhase 3。

## 理由

1. **課題の中心は編集の手間** — ブリーフの課題定義は「編集に手間がかかる → 振り返りループが遅い」。
   デッドタイムカットとハイライト抽出だけでもこの課題は大部分解消でき、スタッツ精度に依存しない。
2. **技術リスクの分離** — 「ポイント区間の検出」（動きの有無・ボールの動きで判定）は
   「スコアの自動判定」（SwingVisionですら精度課題が指摘される）より大幅に易しい。
   易しい方だけで最初の価値が成立する。
3. **サーブ解析は精度リスクが最大** — 姿勢推定は高速なスイング・ラケットの干渉・遠距離で精度が落ちる
   （ブリーフ5-3）。撮影ガイドラインとフォールバック設計を固めてから着手すべき。

## フェーズ計画

### Phase 0 — 編集自動化MVP（最初のリリース）

**ゴール：「アップロードすると、無駄な時間がカットされた動画と共有リンクが返ってくる」**

- 動画アップロード（スマホブラウザ/PWA）
- プリフライトチェック（コート検出・画角判定 → 撮影ガイド表示。検出不能でも縮退モードで編集は実行）
- ポイント区間の自動検出（プレー中/デッドタイムの判定。**人数非依存の活動量ベース＝シングルス・ダブルス両対応**。ターゲット層の主戦場はダブルスであるため、Phase 0の編集価値は最初からダブルスで成立させる）
- デッドタイムカット済み動画の生成（FFmpeg）
- 共有リンク発行（閲覧専用URL、LINEでの共有）
- ユーザーによる区間の手動修正UI（誤検出のリカバリ 兼 学習データ収集）

**この段階で作らないもの**：スコア判定、ショット分類、スタッツ、アドバイス。

### Phase 1 — スタッツとハイライト

**ゴール：「ミスの数と種類が自動で記録され、重要な場面のハイライトができる」**

- ショット分類（サーブ/フォア/バック/ボレー・スマッシュ）。まずシングルスで精度を立てる。
  ダブルスの打者判定は難度が高いため、v1では unknown 許容で段階導入
- ラリー終端イベントの検出（ネット/アウト/ウィナー候補）
- **Phase 1入口のゲート課題**：遠側/近側別のバウンド位置推定誤差を実測し、
  taxonomyの深度しきい値（forcing_depth等）が測定精度で支えられるかを検証してから
  ミス分類を公開する（支えられない場合はしきい値でなくコート半面粒度に落とす）
- ミス分類ルールエンジン v1（[04-miss-taxonomy.md](04-miss-taxonomy.md)）
- ポイントごとのタグ付け → ハイライト動画自動生成（重要ミス・好プレー）
- スコア可視化：**自動判定はせず、ポイント区切りにユーザーがワンタップで勝敗入力する
  半自動方式から始める**（SwingVisionの自動スコアリング精度問題を回避しつつ、正解データを蓄積）
- 自分/相手の識別（コートサイドで判定、ユーザーが初回指定）

### Phase 2 — 分析とアドバイス（最大の差別化）

**ゴール：「ミスの原因分析と継続的なアドバイスが届く」**

- 試合全体の構造化スタッツ → Claude APIによる総合フィードバック生成
  （配球傾向、ミスの偏り、戦術的示唆。[05-tech-stack.md](05-tech-stack.md)）
- アドバイスエンジン＋週次ダイジェスト配信（[07-advice-delivery.md](07-advice-delivery.md)）
- 複数試合をまたいだ傾向分析（ミス率の推移、改善トラッキング）

### Phase 3 — フォーム解析（ユースケース②。2026-07-11にサーブ専用→主要ショット全種へ拡張）

**ゴール：「練習動画からショット別のフォーム解析と参照レンジ比較ができる」**

- 対象ショット：serve / forehand / backhand / smash / volley（詳細設計は[12-form-analysis.md](12-form-analysis.md)）
- ショット別の撮影モード（近距離・単独被写体の専用ガイドライン。試合動画からのフォーム解析はしない）
- MediaPipe Poseによる骨格抽出 → スイング自動分割 → ショット別フェーズ分割 → 指標集約（中央値+ばらつき）
- 関節角度・タイミング指標の算出と参照レンジ比較（[06-pro-reference-data.md](06-pro-reference-data.md)）
- 信頼度が低いフレーム区間の明示と再撮影ガイド（フォールバック必須）
- 段階導入：3a serve（済）→ 3b forehand/backhand → 3c smash → 3d volley（文献レンジの裏取りが各段階の公開ゲート）

## MVPの成功指標（Phase 0）

| 指標 | 目標 |
|---|---|
| **アップロード完了 → 編集済み動画納品**の所要時間 | 動画実時間の1.0倍以内（時間予算は[02](02-architecture.md)。アップロード自体はユーザー回線依存のため別指標） |
| 初回アップロード完遂率 | 80%以上（Wi-Fi待ち・中断再開を含むファネル指標。[09](09-go-to-market.md)） |
| デッドタイム判定の適合率 | 90%以上（プレー区間を誤って削らない方を優先） |
| **区間修正率**（手動修正が必要だった区間の割合） | 10%以下 ※Phase 1の「分類修正率」（ポイント分類の修正）とは別指標 |
| 共有リンクの利用率 | アップロードの50%以上で共有される |
