## 設計原則

不変原則（CLAUDE.md と同一番号。変更にはユーザー合意が必要）：

1. **スマホ1台撮影が前提** — 検出精度の限界を設計に織り込む。信頼度スコアを全解析結果に付与し、低信頼は unknown としてユーザー修正に委ねる（誤った断定より未分類）。
2. **粒度はハードコードしない** — ミス分類・判定基準・アドバイス発火条件はすべてYAML設定として外出しし、コード変更なしで追加・変更できる。
3. **CVパイプラインはステージ独立** — 各ステージの中間出力を保存し、下流のみの再実行を可能に保つ。
4. **動画をLLMに渡さない** — Claude APIへの入力は集計済み構造化スタッツJSONのみ。

追加の設計方針：

5. **自前実装を最小化** — 姿勢推定・物体検出・動画処理・自然言語生成は既存ライブラリ/APIに委ねる。自前で作るのは「テニスドメインのルールエンジン」と「パイプラインの接着」のみ。
6. **編集の価値が先、分析の価値が後** — 精度が課題になるのは「分析」。まず精度リスクの低い「デッドタイムカット・ハイライト・共有」で価値を出し、分析機能を段階的に載せる。
7. **日本ロコはGTM戦術、設計はグローバル** — LINE・オムニ対応は初期市場の手段であり、チャネル抽象・ロケールキー型YAML・court-spec外出しにより、スキーマ・設定レベルで特定市場にロックしない。

他ドキュメントからの参照は「不変原則N」（1〜4）／「設計方針N」（5〜7）と表記する。

## 全体像（1枚図）

```
[スマホ動画] → アップロード → プリフライトチェック（画角・コート検出）
    ↓
[解析パイプライン]
  コート検出 → 選手/ボール検出・追跡 → ポイント区間分割 → ショット分類
    ↓                                        ↓
  イベントストリーム(JSON)          デッドタイムカット指示
    ↓                                        ↓
[ルールエンジン] taxonomy.yaml     [FFmpeg] 編集動画・ハイライト生成
  ミス分類・スタッツ集計                      ↓
    ↓                              [HLS配信・共有リンク・LINE/YouTube]
[Claude API] 構造化スタッツ → 総合フィードバック・アドバイス生成
    ↓
[アドバイスエンジン] advice-rules.yaml → 即時 + 週次配信
```
