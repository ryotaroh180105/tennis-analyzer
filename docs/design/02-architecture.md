- **API層とワーカー層を分離**：動画解析は分単位のバッチ処理。ジョブキュー経由の非同期実行とし、
  進捗はWebSocket/ポーリングでクライアントに通知。
- **成果物はすべてS3互換ストレージ**：原本動画、編集済み動画、ハイライト、イベントJSON、スタッツ。
  コンテナ/ワーカーはステートレスに保つ。

## CV解析パイプライン（ステージ設計）

各ステージは「入力 → 出力（＋信頼度）」が明確な独立ステップ。途中結果はすべて保存し、
下流だけの再実行（例：taxonomy変更時のミス分類のみ再計算）を可能にする。

| # | ステージ | 手法 | 出力 |
|---|---|---|---|
| 1 | コート検出 | 白線検出＋ホモグラフィ推定 | コート座標系への射影行列、コート種別、信頼度 |
| 2 | 選手検出・追跡 | YOLO系検出＋ByteTrack | 選手2名のトラック（画面座標＋コート座標） |
| 3 | ボール検出・追跡 | TrackNet系（時系列CNN） | ボール軌道、バウンド位置候補 |
| 4 | ポイント区間分割 | 選手・ボールの活動量からプレー/デッドタイム判定 | ポイント区間リスト `[{start, end}]` |
| 5 | ショットイベント検出 | ボール軌道の方向反転＋打者側判定 | ショット列 `[{t, player, court_pos}]` |
| 6 | ショット分類 | 骨格特徴（MediaPipe Pose）＋打点位置の分類器 | ショット種別（serve/forehand/backhand/volley_smash） |
| 7 | ラリー終端判定 | 最終ショット後の軌道（ネット到達/バウンド位置/追跡ロスト） | 終端タイプ候補（net/out/in_winner/unknown）＋信頼度 |

**Phase 0で必要なのはステージ1〜4のみ。** 5〜7はPhase 1で追加。

### 信頼度の扱い（設計原則2の具体化）

- 全ステージの出力に `confidence: 0.0-1.0` を付与。
- ステージ7の終端判定が `confidence < 0.6` の場合は `unknown` とし、UIで「未分類」として
  ユーザーのワンタップ修正を促す。修正結果は正解ラベルとして蓄積し、分類器の改善に使う。
- **誤った断定より「わからない」を優先する。** これがSwingVisionの自動スコアリング精度問題への回答。

## イベントストリーム（中間データ形式）

CVパイプラインの出力は正規化されたJSONイベントストリームに統一する。
ルールエンジン・編集指示・Claude APIへの入力はすべてこの形式から派生させる。

```jsonc
{
  "match_id": "m_01H...",
  "video": {"duration_s": 4820, "fps": 30, "resolution": "1920x1080"},
  "court": {"type": "omni", "homography": [...], "confidence": 0.94},
  "players": [
    {"id": "p1", "side": "near", "is_owner": true},
    {"id": "p2", "side": "far", "is_owner": false}
  ],
  "points": [
    {
      "index": 12,
      "clip": {"start_s": 613.2, "end_s": 641.8},
      "shots": [
        {
          "t": 613.5, "player": "p1",
          "type": "serve", "type_confidence": 0.91,
          "contact_court_pos": [5.2, -1.1],
          "landing_court_pos": [3.8, 4.2], "landing_confidence": 0.72
        }
        // ...
      ],
      "terminal": {"type": "net", "confidence": 0.83, "last_shot_player": "p1"},
      "score_after": {"p1": "30", "p2": "15", "source": "user_input"},
      "user_corrections": []
    }
  ]
}
```

ポイント：

- `source: "user_input"` — スコアは半自動（ユーザー入力）。将来自動化しても同じフィールドを使う。
- `user_corrections` — ユーザー修正の履歴を保持し、学習データ化と監査に使う。
- 座標はすべて**コート座標系**（ホモグラフィ変換後、単位m）に正規化。カメラ位置に依存しない。

## 動画編集パイプライン（FFmpeg）

1. **デッドタイムカット版**：`points[].clip` を連結。ポイント間に1.5秒のバッファと
   スコアオーバーレイ（drawtext/ASS字幕）を挿入。
2. **ハイライト版**：ルールエンジンがタグ付けしたポイント（重要ミス・好プレー・長いラリー）のみ抽出。
3. **配信**：HLS（`-f hls`）に変換してストレージへ。共有リンクは署名付きURL。

再エンコードを避けるため、カット点をキーフレームにスナップする（`-c copy` 優先、
スコアオーバーレイが必要な場合のみ再エンコード）。

## データモデル（主要エンティティ）

```
User ─┬─ Match ─┬─ VideoAsset (original / edited / highlight / hls)
      │         ├─ AnalysisJob (stage, status, progress)
      │         ├─ EventStream (JSON, versioned)
      │         ├─ PointRecord (ユーザー修正含む)
      │         └─ MatchFeedback (Claude生成、構造化)
      ├─ TaxonomyConfig (ユーザー/バージョンごとのYAML参照)
      └─ AdviceLog (配信履歴、既読、リアクション)
```

- `EventStream` と `MatchFeedback` はバージョン付き。taxonomyやモデルの更新で再計算しても
  過去の結果を上書きしない。
