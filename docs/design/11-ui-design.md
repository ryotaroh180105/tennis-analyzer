# 11. UI設計（Phase 0〜1）

対象：PWA（モバイルファースト）。Phase 0 の4画面＋共有視聴ページを詳細化し、
Phase 1（スタッツ）は方針のみ。実装は [10](10-phase0-implementation-plan.md) のAPI契約に対応する。
ビジュアルモック：`docs/overview/ui-mock.html`（スナップショット。正はこの文書）。

## UI原則（設計の不変原則をUIに翻訳したもの）

1. **誠実さを可視化する** — 信頼度・unknown・縮退モードを隠さない。
   「解析できなかった」は失敗表示ではなく「あなたが直せる場所」として提示する（不変原則1）。
2. **修正は1タップ＋ドラッグ** — 区間修正・分類修正がプロダクトの学習ループの入口。
   修正UIは機能ではなく主要動線として設計する。
3. **親指圏で完結** — 主要操作（アップロード・共有・修正）は画面下部のアクションバーに置く。
   片手・コートサイド・屋外光での利用が前提。
4. **待ち時間を不安にしない** — 解析は分単位。進捗は段階名で示し、
   「閉じてOK、終わったらLINEに届く」を常に明示する（ポーリング。[02](02-architecture.md)）。
5. **言葉は利用者の言葉** — 「ingest」「preflight」を画面に出さない。
   「動画を整えています」「コートを探しています」。文言は本書の文言表が正。

| `--surface-raised` | `#ffffff` | `#1a241e` | カード |
| `--ink` | `#17211c` | `#eef3ef` | 主文字 |
| `--ink-secondary` | `#5a6b61` | `#9fb0a5` | 補助文字 |

| `--ball` | `#d9e021`（オプティックイエロー） | `#e4ec3a` | アクセント。**1画面1箇所**（現在位置・新着バッジ） |
| `--alert` | `#c2472e` | `#e06a50` | 破壊的操作・エラーのみ。装飾に使わない |
| `--line-hair` | `#dde5dd` | `#2a362e` | 罫線 |

- 型：本文はシステムサンセリフ（`system-ui, "Hiragino Sans", "Noto Sans JP"`）。
  数値（時間・スタッツ）は `font-variant-numeric: tabular-nums`。タイムコードは等幅。
  型スケール：13 / 15（本文） / 17 / 22 / 34（ヒーロー数値のみ）。
- 角丸12px・カード影は極薄1段のみ。色はセマンティック（緑=プレー、砂=カット）に
  意味を固定し、装飾転用しない。
- 両テーマ必須（`prefers-color-scheme` ＋ `data-theme` 上書き。トークンレベルで切替）。

## シグネチャ要素：区間タイムライン・リボン

全画面を貫く中心コンポーネント。動画の時間軸を1本の帯で表し、
**コート（緑）とその間の砂（デッドタイム）**というテニスコートの実風景を意味に転写する。

```
|■■■■■■■□□■■■■■■■■■□□□■■■■■□□■■■■■■■■■■■■|
 緑=プレー区間（残る）   砂=カット（薄く残す=「消した」でなく「畳んだ」）
 低信頼区間は緑の彩度を落とす（触ると「自信がありません。確認してください」）
 ● 再生ヘッド＝ボールイエローのドット（画面唯一のアクセント）
```

- **閲覧時**：リボンは読み取り専用のミニマップ。タップで該当区間へシーク。
- **修正時**（区間修正UI）：同じリボンが編集面に変わる。区間端のハンドルをドラッグ、
  砂部分をタップ→「この区間を残す」、緑部分を長押し→「この区間を削る」。
  PATCHは `base_revision` 付き（[10](10-phase0-implementation-plan.md)。409時は「他の画面で
  編集されました。最新を読み込みます」）。
- 低信頼（confidence < 0.7）の区間端は彩度低下＋波線ハンドルで表示。
  **信頼度の数値は出さない**（数値は専門家の言葉。UIでは状態で語る）。

## 画面マップ

```
[共有視聴 /s/{token}]（未ログイン）──登録導線──┐
                                              ▼
[ホーム=試合一覧] ─┬─ [アップロード（シート）]
                   └─ [試合詳細] ── [区間修正（モーダル全画面）]
（Phase 1+: 試合詳細にスタッツタブ、ホームに傾向カード）
```

## 画面仕様（Phase 0）

### 1. ホーム（試合一覧）

- 構成：上=今月の利用（Free: 「今月 1/1 本」）、中=試合カード列、下=固定アクションバー
  （中央に大きく「＋ 動画を追加」）。
- 試合カード：サムネイル＋タイトル＋日付＋状態チップ＋ミニリボン（完了後）。
- 空状態は最初の行動を指す：「過去に撮った試合動画を1本、そのまま入れてみてください。
  画角が悪くても大丈夫 — まず編集して返します」（オンボーディング枠外。[09](09-go-to-market.md)）。

### 2. アップロード（ボトムシート）

| 状態 | 表示 | 文言（正） |
|---|---|---|
| 選択直後 | ファイル名・サイズ・推定時間 | 「4.2GB — Wi-Fiでの送信をおすすめします」 |
| Wi-Fi待ち | 待機カード＋切替ボタン | 「Wi-Fiを待っています。接続したら自動で送信します」／「モバイル回線で今すぐ送る」 |
| 送信中 | 進捗バー＋残り時間。**中断・再開はUIイベントにしない**（裏で自動再開） | 「送信中 34% — アプリを閉じても続きます」 |
| 完了 | 解析開始へ自動遷移 | 「受け取りました。解析をはじめます」 |
| 失敗（再開不能） | 理由＋再試行 | 「送信できませんでした（通信が不安定です）。もう一度試す」 |

### 3. 試合詳細

- 上：プレーヤー（完了後）または進捗ステージカード。
- 進捗は matches.status を利用者の言葉で（[10](10-phase0-implementation-plan.md) の状態対応）：

| status | 表示 |
|---|---|
| queued/prechecking | 「動画を確認しています」 |
| ingesting | 「動画を整えています（1/3）」 |
| analyzing | 「プレーを探しています（2/3）」 |
| editing | 「編集しています（3/3）」 |
| done | プレーヤー表示 |
| failed | 「解析できませんでした：（failure_reason別の文言表）＋やり直す」 |

- 常時表示：「閉じてOK。終わったらLINEでお知らせします」（未友だち時は「メールで〜」）。
- 完了ビュー：プレーヤー＋リボン＋要約行（**ヒーロー数値はここだけ**：
  「1:42:10 → **31:24**」保存時間の圧縮を主役に）＋アクションバー
  「共有する」「区間を直す」「保存」。
- 縮退モード時（degraded=true）：黄土色のインフォバー
  「コートを見つけられなかったため、動きだけで区間を判定しています。
  精度が低い場合は区間を直してください。次回の撮り方 →」。**エラー色にしない**。

### 4. 区間修正（全画面モーダル）

- 上2/3=プレーヤー（現在区間をループ）、下1/3=拡大リボン＋ハンドル。
- 操作：端ドラッグ（±0.5s単位スナップ）／砂タップ=復活／緑長押し=削除／取り消し（直前3操作）。
- 完了：「この内容で作り直す」→ recut（[10](10-phase0-implementation-plan.md)）。
  処理中も旧版は視聴可能（世代管理）。
- 修正はそのまま学習データになる旨を初回のみ1行表示：
  「直してくれた区間は、判定の改善に使われます」。

### 5. 共有視聴ページ（/s/{token}、未ログイン）

- 構成：プレーヤー最上部（サムネイル→即再生）＋リボン（読み取り専用）＋
  ハイライトチップ（Phase 1）＋**登録導線は1つだけ**。
- Phase 0 の導線文言：「自分の試合も、撮って送るだけ」。
  Phase 2（クレーム導線）で「この試合に映っていますか？ 自分のプレー集を受け取る」に差し替え
  （[09](09-go-to-market.md) — 約束するのはプレー集＋活動サマリ。スタッツと言わない）。
- 相手の個人情報は出さない（既定。[07](07-advice-delivery.md)）。フッターに
  「この動画の削除を依頼する」（削除請求導線。[08](08-operations.md)）。

## Phase 1 のスタッツUI（方針のみ）

- **dataviz スキルの方法論に従う**：フォーム選択→役割ベースの色→パレット検証
  （`validate_palette.js` を本書のトークンで実行）→マーク仕様→ホバー/タップ層→
  アクセシビリティ。チャートを作る前に必ず同スキルを読むこと（実装時の規約）。
- 系列色はブランドの `--court` を series-1 に据え、検証済みのカテゴリ順で固定。
  **unknown は常に灰色・最後尾・「未分類 n 件」ラベル付き**で、分母から除外して表示
  （[04](04-miss-taxonomy.md)）。
- スタッツの主役は「前回との差分」（[07](07-advice-delivery.md)）。単発の円グラフより
  傾向のスパークライン＋差分チップを優先する。

## アクセシビリティ・品質フロア

- タップターゲット44px以上。リボンのハンドルはマークより大きい当たり判定。
- 色だけに意味を持たせない：砂区間は斜線テクスチャ併用、低信頼は波線ハンドル併用。
- キーボードフォーカス可視・`prefers-reduced-motion` 尊重（リボンのアニメは無効化）。
- 屋外直射光を想定しコントラストはWCAG AA以上（`--ink` on `--surface` = 12:1超）。
- 文言はすべて `users.locale` から引く辞書化（[10](10-phase0-implementation-plan.md)。設計方針7）。
  本書の日本語文言が `ja` 辞書の正。
