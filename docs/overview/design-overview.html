テニス動画分析アプリ 設計概要

スマホ1台の動画から、編集済み動画・スタッツ・ミス分析・継続アドバイスを自動生成する。 設計ブリーフの7論点すべてに結論を出し、リポジトリの docs/design/ に詳細を分冊した。

MVP = 編集自動化（Phase 0） 粒度はYAMLで可変 スマホ1台撮影が前提 日本語ネイティブ

Decisions

7つの論点への結論

論点決定
1MVPのスコープ 試合分析（①）から。ただし初回リリースは「デッドタイムカット＋共有」のみに絞る。サーブ解析（②）はPhase 3
2撮影要件 強制せず「推奨＋アップロード時プリフライト自動判定＋改善ガイド」の3段構え
3ミス分類の初期粒度 ショット4分類 × 結果 × 強制/非強制。軸・判定式・しきい値はすべて taxonomy.yaml に外出し
4外部ツール連携 MediaPipe Pose・TrackNet系・FFmpeg・Claude API（claude-opus-4-8）・R2/S3・LINE Messaging API
5プロ比較の参照データ 放送映像は権利リスクで不採用。バイオメカ文献レンジのYAML化＋契約コーチ撮り下ろしの2本立て
6継続アドバイス配信 即時＋週次ダイジェスト＋トリガー型（週1上限）。チャネルはLINE主軸。発火条件もYAML
7スコア自動判定 自動化しない（SwingVisionの精度問題を回避）。ポイント区切りでワンタップ入力の半自動方式

Roadmap

フェーズ計画 — 編集の価値が先、分析の価値が後

Phase 0

編集自動化

アップロード → ポイント区間検出 → デッドタイムカット → 共有リンク。スタッツ精度に依存しない最初の価値。

Phase 1

スタッツ＆ハイライト

ショット分類、ミス分類ルールエンジン、ハイライト自動生成、半自動スコア入力。

Phase 2

分析＆アドバイス

Claudeによる総合フィードバック、週次ダイジェスト、複数試合の傾向分析。最大の差別化。

Phase 3

サーブ解析

骨格抽出→フェーズ分割→文献レンジ比較。精度リスク最大のため専用撮影モードと再撮影フォールバックを前提。

Pipeline

CV解析パイプライン — ステージ独立・信頼度付き

P01. コート検出白線＋ホモグラフィ
P02. 選手検出・追跡YOLO系＋ByteTrack
P03. ボール追跡TrackNet系
P04. ポイント区間分割プレー/デッドタイム
P15. ショット検出軌道反転＋打者判定
P16. ショット分類骨格＋打点位置
P17. 終端判定net / out / winner / unknown

全ステージが confidence を出力。低信頼は「unknown」としてユーザー修正に委ね、 修正結果を学習データとして蓄積する。中間出力はすべて保存し、taxonomy変更時は下流のみ再計算。

Principles

設計原則

01誤った断定より「わからない」

SwingVisionの自動スコア精度問題への回答。低信頼な判定はunknownに落とし、ワンタップ修正で精度表示が上がるインセンティブ設計。

02粒度はハードコードしない

分類軸・判定式・しきい値・アドバイス発火条件はYAML宣言。カテゴリ追加＝設定編集で、コード変更ゼロ。

03自前実装は接着部分だけ

姿勢推定・検出・動画処理・文章生成は既存ライブラリ/APIへ。自前で作るのはテニスドメインのルールエンジンとパイプライン統合のみ。

04動画をLLMに渡さない

Claude APIへの入力は集計済みスタッツJSONのみ。コスト・再現性・プロンプトキャッシュ効率のため。ドメイン知識はsystemに固定しキャッシュ。

Positioning

競合との差別化

領域主な競合本アプリの立ち位置
スタッツ・ハイライト編集SwingVision（iOS専用） 日本語ネイティブ / オムニコート前提 / クロスプラットフォーム（PWA）
